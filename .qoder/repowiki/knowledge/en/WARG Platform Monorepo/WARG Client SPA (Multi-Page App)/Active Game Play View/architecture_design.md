Three-file leaf module composing a single-page game view:
- `game.html` is the shell — shared app-shell (left sidebar nav, topbar, right friends panel) plus the main content area (`#game-map`, feedback/comments section) and the Play Modal dialog (`#play-modal-overlay`). It loads shared CSS tokens, then this page's CSS, then the script chain `config.js → db.js → api.js → home.js → game.js`.
- `scripts/game.js` is the entry point. On `DOMContentLoaded` it reads `?id=` from the URL, calls `/api/game/{id}/start` + `/state` to bootstrap a session, watches `navigator.geolocation` for live player position, and wires up like/dislike/flag/comment interactions. Minigame orchestration is delegated to reusable components imported as ES modules: `PlayModal`, `FlagModal`, `MapModal`, `CameraCapture`, and a registry via `getMinigameHandler` in `components/minigame-handlers.js`. Sensor telemetry is collected through `sensors.js` (`startSensors`, `logPosition`, `getSensorDataAndReset`) and synced offline via a `BroadcastChannel('warg_sync_channel')` listening for `SYNC_RESULT` messages dispatched by the service worker.
- `styles/game.css` styles the map placeholder, timeline nodes/edges/popover, the play modal (desktop centered + mobile bottom-sheet via `@media (max-width: 768px)`), the camera capture UI, and the comment/discussion thread.

Dependency direction inside the module: HTML → JS imports → sibling `components/*` and `sensors.js`; CSS depends only on shared design tokens from `styles/tokens.css`. The page does not import other pages' scripts beyond the shared infrastructure layer.
