The repo is a multi-service monorepo where each child package is independently deployable but coordinated at the edge:
- `vercel.json` is the single routing entry point: it rewrites `/` to `client/home.html` and proxies all static assets under `styles|scripts|assets|test-results|tests|node_modules` into the `client/` tree, so Vercel serves the SPA while the Express server (`server/`) and FastAPI service (`ai_engine/`) are hosted separately on Render/Aiven.
- Cross-service communication is HTTP-based: the Express server calls the AI engine's FastAPI endpoints for image-scoring features (Shape Matching, Colour Matching) referenced in the README's Advanced Tier; the client talks only to the Express API.
- Shared identity flows through `express-session` + `passport-google-oauth20` declared at the root `package.json`, which both the Express server and any client-side auth logic depend on — the root lockfile is the single source of truth for these cross-cutting dependencies.
- The database layer (MySQL with SRID 4326/WGS 84 spatial extensions, accessed via Sequelize) is owned by `server/` and consumed indirectly by `ai_engine/` through the API boundary rather than direct DB access.
