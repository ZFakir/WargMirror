Three thin controller modules under `server/src/controllers/`, each exporting handler functions consumed by Express routes:
- `feedbackController.js` — single `submitFeedback` handler that maps camelCase request fields to snake_case Sequelize model attributes on `UserFeedback`, optionally attaching `user_id` from an authenticated `req.user`.
- `adminController.js` — admin-only CRUD/mutation handlers (`getFlags`, `resolveFlag`, `searchUsers`, `toggleBanUser`, `deleteGame`, `deleteComment`) built on Sequelize models (`User`, `Flag`, `Arg`, `Comment`) with `Op.in` / `Op.like` queries; mutation handlers write `resolved_by = req.user.user_id` to tie actions to the current admin.
- `aiController.js` — five `evaluate*` handlers (`evaluateShape`, `evaluateColour`, `evaluateTexture`, `evaluateSift`, `evaluateSymmetry`) that accept multipart images via `multer`-populated `req.files`, build a `FormData` payload, and forward it via native `fetch` to an external AI service at `process.env.AI_SERVICE_URL` (default `http://localhost:8000`) on endpoints like `/api/v1/sam-extract`, `/api/v1/hsv-match`, etc. No local ML logic lives here — this module is purely a request-shaping proxy.

Dependency direction is one-way: controllers → `../models` (Sequelize) and, in `aiController`, an out-of-process HTTP client. There is no shared base controller or middleware inside this scope.
