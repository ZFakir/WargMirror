Three-file MVC slice under `server/src`:
- `routes/gameRoutes.js` declares Express router endpoints (`/:argId/start`, `/:argId/state`, `/:argId/waypoint/:waypointId/arrive|submit`, `/:argId/abandon`) and wires middleware — `requireAuth` + `antiSpoofing` on the arrive endpoint only.
- `controllers/gameController.js` is the sole business layer: it imports Sequelize models (`GameSession`, `Waypoint`, `WaypointEdge`, `Minigame`, `WaypointProgress`, `MinigameAttempt`, `LocationEvent`) from `../models`, runs all mutating operations inside a single `sequelize.transaction()`, and exposes stateless async handler functions attached via `exports.*`.
- `models/GameSession.js` defines the `game_sessions` table schema (composite PK of `user_id`+`arg_id`, ENUM status) using Sequelize DataTypes directly against the shared `../config/database` instance.

Internal flow: `startGameSession` creates a session and seeds `WaypointProgress` for every waypoint (roots unlocked, others locked); `getGameState` lazily unlocks root nodes and auto-completes the session when no unlocked nodes remain; `submitMinigame` dispatches validation by `game_type` (`gps_proximity`, `text_answer`, `qr_barcode`, `plaque_scan`), calls an external AI OCR service at `${AI_SERVICE_URL}/api/v1/ocr-match` for plaque scanning, then evaluates edge conditions via the local `evaluateConditions` helper to unlock successor waypoints. Dependency direction is one-way: routes → controller → models; the controller also reaches out to an external HTTP AI service.
