## 1. What is missing and why it matters for scoring

Dead pages, unreferenced scripts/styles, and placeholder imagery are exactly what a marker poking around the deployment finds ("why does this 404 / why is there a stock photo here?"). They signal an unfinished product. The register calls out Lorem Picsum placeholders in authoring pages (post-P2-9), OS-artifact cleanup through source control, and the undocumented `update_nav.py` nav generator. Polish and completeness marks come from a repo with no visible leftovers.

- Grep for picsum/placehold URLs on main found **no** Lorem Picsum URLs — but the register says authoring pages (create/edit WARG) contain placeholder imagery; likely via `client/assets/` defaults or empty-state markup. Verify per-page during subtask 2.

## 3. Implementation subtasks

1. **Reference sweep (read-only first)**: for each page/script/style, grep navigation links + `import`/`script src` references. Produce a keep/referenced-vs-orphan table in the PR. Candidates must be manually confirmed (a page reachable only via direct URL from user flows, like `friend-profile.html`, is NOT dead).
2. **Placeholder imagery**: inspect `create_warg.html` / `edit_warg.html` cover flows; replace any placeholder/stock imagery with either the real upload path (IP-P2-9) or a neutral in-repo SVG/CSS placeholder that reads as intentional (not stock). Ensure empty-state visuals in authoring flows are deliberate.
3. **Delete confirmed dead files** in one commit (git tracks history — deletions are recoverable). Update any references in the same commit so the suite stays green.
4. **Asset hygiene**: check `client/assets/` and repo root for unused binaries; ensure `.gitignore` covers OS artifacts; commit removal of tracked artifact files if any exist.
5. **`update_nav.py` decision**: either (a) document it in `client/README`-section or root README ("Navigation blocks are generated by `update_nav.py`; edit nav by running `python update_nav.py` after changing the template in the script") with a header comment inside the script, or (b) replace it with a maintainable shared-nav strategy (e.g. a JS-injected nav component). Option (a) is the cheap, honest fix; option (b) only if time allows. Record the decision.
6. **Verify**: full Playwright suite + manual nav walk across all pages.
